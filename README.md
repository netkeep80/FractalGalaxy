# FractalGalaxy

Экспериментальный движок **фрактальной материи**: интерактивные тела, процедурно определяемые в кубических областях, с раздельными объёмным и поверхностным уточнением.

## Центральная гипотеза

- `B` — исходная пространственная иерархия материи, детерминированно вычисляемая из `seed`, версии генератора и адреса.
- `D` — разреженная иерархия **результатов** воздействий, а не журнал действий.
- `M = Resolve(B, D)` — текущее материальное состояние. Ни GPU-меш, ни текущая глубина LOD не являются состоянием мира.
- Физические тела могут отделяться и сращиваться. Контакт и механическое соединение **не тождественны** материальному слиянию.
- `FractalRing` — модель независимых физических тел и их пространственных кадров, а не дерево временных треугольников.

См. [архитектурную гипотезу](docs/architecture.md), [план проверок](docs/verification-plan.md) и нативные [Requirements](requirements/).

## Стадия проекта

Только спецификация кандидата: **алгоритмы и физический движок ещё не реализованы**. Требования имеют `accepted: false`, `current: false` до отдельного решения Автора. Не путать RepoGuard CI с подтверждением предметной корректности.

## RepoGuard v6.0.1

Workflow в `.github/workflows/repo-guard.yml` закрепляет точный upstream commit `74db97791e6da8a75287164f0d0b41579108f114` (tag `v6.0.1`) и сравнивает exact PR `BASE/HEAD`.

**Bootstrap caveat:** исходный `main` содержит только `LICENSE` и не имеет Requirements. Проверка первого bootstrap-PR ожидаемо может завершиться RED по baseline J1/J2. Не обходить её фиктивными отношениями, отключением проверок или утверждением о GREEN. После принятия и bootstrap-merge требуются повторная проверка на новой базе и отдельная настройка required status check в GitHub branch protection/ruleset; workflow не создаёт защиту ветки автоматически.
