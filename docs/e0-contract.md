# E0 — конечный проверочный профиль FractalMatter

**Статус: КАНДИДАТ.** Это ограниченный исполнимый контракт для проверки гипотез, а не решение об архитектуре всей игры. Отдельное принятие Автором ещё требуется. Источник проблем — независимый аудит PR #1, F-001…F-016.

## 1. Область, координаты, вещество и разрешение D

Материальные координаты x относятся к **исходному процедурному корню**, а не к мировой позиции. Базовый домен E0: куб Ω=[-1,1]³; уровни уточнения 0…5. Для E0 каноническое материальное поле B(x) вычисляется по фиксированному полному процедурному уровню N=5 (или эквивалентной точной аналитической функции). Более грубые узлы — только агрегированное **представление** этого же поля; операция Refine не меняет его значения. При запросе B(x) канонический лист определяется на уровне N независимо от раскрытого визуального дерева. За пределами Ω запрос явно отклоняется. Точки общих границ подкубов назначаются по полуоткрытому правилу: нижняя граница включается, верхняя исключается, кроме максимальной границы корня.

Материальное значение: `EMPTY` либо `SOLID(material_id, density)`, где `material_id` — непустой идентификатор, `density` — конечное число f64 >0. Отсутствие записи D означает `INHERIT`, а не `EMPTY`.

D является **снимком результата**, не списком событий. Допустимые пространственные записи — канонические ячейки с `EMPTY` либо `SOLID`; внутри дерева более глубокая запись перекрывает значение более общего предка. При одновременном конфликте на одной канонической глубине и области снимок отклоняется; порядок вставки или обхода не выбирает победителя. `M(x)=Resolve(B,D)(x)` возвращает значение наиболее специфичной применимой записи D, иначе B(x). Семантическая версия B, D и разрешения масок явно записывается в снимке. Наложения материалов и реальные смеси в E0 не поддерживаются (RQ-01/02).

Строгое равенство полей при Refine — равенство `M(x)` по **одним и тем же** исходным координатам для поддерживаемых запросов, без физического воздействия и при неизменных B/D/Γ. Равенство масс/моментов — отдельная, более слабая проверка.

## 2. Начальное значение, состояние генератора и Γ

Различать:
- **начальное значение генератора (seed)**: вход исходного процедурного корня;
- **состояние генератора**: вычисляемое целочисленное значение конкретной дочерней области;
- **исходный процедурный контекст Γ**: корень, версия, адресная родословная, состояния и неизменяемые входы исходных процедурных соседей; его нельзя путать с текущим физическим `FractalRing`.

**Пробный Derive32 vE0-1, только для E0:** все вычисления над uint32 по модулю 2³². Для ветви i=0…7: `x=parentState XOR ((i+1)*0x9e3779b9 mod 2^32)`; `x ^= x >>> 16; x=imul(x,0x7feb352d); x ^= x>>>15; x=imul(x,0x846ca68b); x ^= x>>>16`. Выход: `childState=x`. Для поверхности в E0 используются ветви 0…3 с отдельным доменом/ключом типа; не переиспользовать объёмные ключи для тех же ячеек. Точные тест-векторы объёма: для parent 0x00000000, ветви [0,1,3,7] → [0x01fce552,0x04f8d29e,0x6ba5a157,0x60f3d8ca]; для parent 0x12345678 → [0x8ff7a29e,0x7d0ecaf2,0x31e4401c,0x7f73ae6e]. Это **не** утверждение побитовой совместимости со старым C++ RND; старое наследование служит источником идеи.

Граничная зависимость E0 должна быть реально наблюдаемой, а не фиктивным словом в документации. Контрольная процедурная фикстура: для канонической области a на уровне N=5 определять `h(a,Γ)=(((state(a) & 15)-8)/128)+(alpha_neighbor/16)`; занятость `z ≤ h`, плотность 1. `alpha_neighbor` — зафиксированное при создании исходного контекста целое число от исходного соседнего процедурного ключа, а не от текущего `FractalRing`. Новая контрольная версия фикстуры с изменённым `alpha_neighbor` должна менять соответствующее h. Общий исходный ключ границы и правила значения для отсутствующего соседа фиксируются внутри Γ; отсутствие обязательного входа — ошибка. Материализированный физический сосед не нужен.

Набор поддерживаемых уточнений конечен (уровень ≤5). Для переносимого `Save(fragment)` все данные/контекст, включая требуемые входы **за пределами маски** фрагмента, входят в снимок либо ссылаются на версионированное immutable-хранилище, гарантированно доступное после удаления физических родителей. Холодная загрузка проверяется в чистом процессе и на **не запрошенном ранее адресе**.

## 3. Ячейки, граница и маска

Разбиение куба на 8 и параметрической грани на 4 должно полностью покрывать родителя, а не только иметь непересекающиеся потомки. Клеточная грань, внешняя граница области занятого вещества и интерфейс двух материалов различаются. При разрыве плотности на стыке соседей односторонние пределы могут различаться; канонический запрос M(x) имеет один результат по принятому правилу границ.

## 4. Физические экземпляры и переходы

Материальный **лист-владелец** хранит уникальный `material_instance_id`, свою маску/материальное поле B/D/Γ. Разные material_instance_id могут использовать один и тот же immutable генератор B и тот же seed, оставаясь разными массами. Составной `FractalRing K` не владеет самостоятельным B/D и суммирует характеристики уникальных материальных потомков. Физический лес без циклов: у узла максимум один текущий родитель.

- `Contact(A,B)` без явного воздействия **вообще не меняет** лес, число корней, B/D, ID и параметры движения.
- `Attach(A,B)` принимает два **разных живых независимых корня**, совместимых по жёсткой кинематике. Создаёт новый K с отдельным кадром, делает A,B детьми и сохраняет их seed/B/D/Γ/ID. Входы с одинаковым, отсутствующим или некорневым ID либо несовместимой кинематикой отклоняются **атомарно**; произвольное столкновение не является Attach.
- `Detach(A)` снимает связь с физическим родителем, не меняя процедуру генерации, принадлежность материи и мировые координаты точек A. После отделения от жёсткого K без импульса `v_A=v_K+ω_K×(c_A-c_K)`, `ω_A=ω_K`, где все величины в одном мировом кадре.
- `Split(root, P_left, P_right)` для явного двоичного разреза переносит **исходное** M на две маски с `P_left ∪ P_right=Ω` и `P_left ∩ P_right=∅` как на множества владельцев. Для плоскости `f(x)=0`: `P_left: f(x)<0`, `P_right: f(x)≥0`. Замыкания геометрических областей могут иметь общую поверхность, физическое владение — никогда. В точках сохраняемого вещества `M_i(x)=M_before(x)`, включая D. Исходный владелец прекращает существовать, у двух новых материальных экземпляров новые ID; исходные B/D/Γ можно структурно разделять без удвоения массы. Неавтоматические законы разрушения остаются RQ-07.
- Фактическое сращивание `Fuse` (новое вещество) не входит в E0.

При Attach мировая координата **каждой соответствующей материальной точки** до/после совпадает. Для ребёнка с неизменными локальными координатами `T_child^K=(T_K^W)^(-1)T_child^W`. При переносе материального начала координат должно применяться соответствующее обратимое преобразование адресов. Для Attach E0 требует совместимых скоростей твёрдого движения, а не придумывает закон ударного сцепления: существует (v_K, ω_K), согласованный с v_A, v_B, ω_A, ω_B в данный момент. При отсутствии решения команда отклоняется. Внешние силы/импульсы между этими проверками отсутствуют.

## 5. Масса, инерция, кэши и численные эталоны

Постоянная плотность ρ=1 в кубе Ω: `m=8`, центр масс `(0,0,0)`, `I_COM=(16/3,16/3,16/3)`. При x=0: массы 4/4 и центры ±1/2. При x=1/4: массы 5 и 3, центры x=-3/8 и +5/8, собственные диагонали инерции (10/3,445/192,445/192) и (2,73/64,73/64). Эти разрезы — численные регрессии, **не** доказательство произвольного разреза: x=1/4 — граница octree уровня 3.

**Решающая ненодовая фикстура:** `x+y=1/2`, с масками `x+y<1/2` и `x+y≥1/2`. Массы равны `23/4` и `9/4`; меньшая часть — треугольная призма с центром масс `(1/2,1/2,0)`, большая имеет центр `(-9/46,-9/46,0)`. Наклонная плоскость не состоит из граней конечных кубических листьев.

Проверять полный тензор инерции в общем мировом базисе, включая внедиагональные компоненты, а не только сумму масс/диагонали. Для повернутого некубического фрагмента тест должен давать ненулевой Ixy. После изменения D старый кэш массовых моментов недействителен.

Для малых аналитических f64 фикстур с координатами порядка 1 кандидатом является абсолютный покомпонентный допуск `1e-12`, кроме целочисленных адресов/семян/ID (точное равенство). Нечисловые NaN/Infinity запрещены. Для ориентации сравнивать матрицы вращения в одной системе координат (компонентно, ≤1e-12) с учётом эквивалентности кватернионов q и -q. Для далёких мировых координат эти допуски не заявлены; метрика точности — RQ-05.

## 6. Холодное сохранение/восстановление

`Save(World)` содержит исходное M через B/D, Γ, семантические версии B/D/Γ/масок, material_instance_id, ownership masks, физические ID и связи, кадры, линейные и угловые скорости. `Load` в новом процессе с пустыми кэшами восстанавливает наблюдаемую структуру и допускает **дальнейшие холодные Refine-запросы**. Неразрешимая ссылка, отсутствующий обязательный Γ, цикл/двойной родитель, повторный ID и неподдерживаемая версия дают атомарный отказ без частичной публикации мира.

## 7. Пределы E0

В E0 допускаются: заданные аналитические поля, версии Derive32 vE0-1, конечный CPU-домен, явные маски Split, явные команды Attach/Detach, жёсткое движение, аналитические оракулы. Не входят: реальный алгоритм разрушения, collision/adhesion law, Fuse, внешняя самогравитация, точность приближённой гравитации, GPU meshing, бесконечная глубина, миграция старых форматов. Все названные ограничения — **предложение для Author review**, не принятое решение.
